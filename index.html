Project 01 / 04

Flutter mobile app

Pick A-Frame

A cross-platform app for gallery owners, artists, and frame shops in Kuala Lumpur. Upload an artwork, choose a frame, and see the finished piece on a wall before anything is made.

My role
UI
Type
Mobile app · Team project
Platform
Flutter + Firebase
Built for
Galleries, artists, frame shops
Status
Completed

The goal

Custom framing is hard to picture. You choose a moulding from a small sample, and you only see the real result after it's cut and assembled. Pick A-Frame lets people see the result first.

My role

I was responsible for the UI of the app: the layout, visual style, and the screens you see below.

Key features

01

Upload your artwork

Start from a photo of the artwork (JPG, PNG, or HEIC, up to 25 MB) and preview it at 1:1 scale in real time.

02

Browse the moulding catalog

Search mouldings, filter by material, sort by profile width, and compare prices per metre.

03

Find frame shops in KL

A map of frame shops around Kuala Lumpur, with each shop's address and the mouldings it stocks.

04

Design the frame

Pick a finish (paint, wood, metal, ornate), moulding colour and profile, lighting angle, and matting, with live outer dimensions.

05

See it on a wall

Hang the framed piece in a virtual room. Change the wall colour, zoom and lighting, and show a sofa for scale.

Tech

FlutterDartFirebaseGoogle MapsMobile UI/UX

Smart Campus Parcel System

A parcel collection and delivery system for a campus, built around a custom singly linked list priority queue with CSV file sync.

Type
Console app
Language
C++
Core structure
Linked list priority queue
Status
Completed

The program

=== Smart Campus Parcel System ===
1. Parcel Intake, Sorting & Processing (Module 1)
2. Parcel Service & Collection (Module 2)
3. Collection Counter & Delivery Resources (Module 3)
4. Parcel Activity & Record Management (Module 4)
5. Parcel Category Organisation (Module 5)
0. Exit
Choice: 2

=== Module 2: Parcel Service & Collection ===
1. Create service request
2. View active requests (By ID / By Priority)
3. Peek next request
4. Process next request
5. Cancel request
0. Back to Main Menu
Choice:

How the queue works

P1Urgent
→
P2Express
→
P3Normal
  • Requests are kept in a sorted singly linked list, so the most urgent parcel is always at the front.
  • Staff can peek at or process the next request, view requests by ID or by priority, and cancel requests.
  • Each service request gets an ID, which is used to collect the parcel.
  • Data is synced to CSV files so records persist between runs.
